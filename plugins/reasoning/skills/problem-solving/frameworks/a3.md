# A3

## When it fits

Operational improvement needing a written case.

## Process

You are executing the A3 framework within the problem-solving skill. Write
the case as eight sections, in order:

1. **Background** — why this matters, who's affected, what's at stake.
2. **Current condition** — what's happening now, as evidenced, not as
   assumed.
3. **Problem statement** — the gap between current condition and what's
   needed, stated in one or two sentences.
4. **Target condition** — what "solved" looks like, specifically enough to
   check against later.
5. **Root cause analysis** — the causal chain behind the problem
   statement. Apply the same root vs. `root_candidate` test as
   `root-cause-analysis.md`: label a cause `root` only when a specific
   evidence entry ties it directly to the problem statement; otherwise
   it's a `root_candidate` with the gap named.
6. **Countermeasures** — actions that address the causes found in section
   5, not the symptom in isolation.
7. **Action plan** — who does what, and by when, for each countermeasure.
8. **Follow-up** — how and when the target condition will be checked
   against what actually happened.

A section has content only when it states something specific, drawn from
evidence, a named assumption, or reasoning traceable to one of those.
Restating the section's title in sentence form, or filling it with a
generic statement that would apply to any problem, does not count. If the
input doesn't support a section, say so directly in that section — "no
evidence available for X" is content; a padded paragraph that says nothing
is not, even though it fills the space.

## Output block

Emit the `a3` block from `references/contract.md`, with fields
`background`, `current`, `problem`, `target`, `causes`, `countermeasures`,
`plan`, `follow_up` — one per section above, in the same order.

## Stop when

All eight sections have content.
